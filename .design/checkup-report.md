# 架构规范复查报告

日期：2026-10-06。对象：assets/raw_design/settings/architecture.md。方式：Design Partner checkup 静态文档/源代码审查；不是整款游戏 UI 或性能验收。

## 结论摘要

规范已正确记录技术栈、BaseEntity、虚空实体、prefab 分目录与先确认后实施的原则，但尚不适合作为无条件执行的重构说明。最主要的风险是关卡配置与临时属性的保存分类不明确，以及历史机制基线与当前已提交渲染实现发生漂移。

## 应保留的决定

- Three.js + JavaScript，浏览器运行游戏逻辑；Node.js 管理资源与既有构建服务。
- 实体和标签各自具有 BaseEntity 许可，保留或替换下层交由实体行为。
- 前端不回写 prefab；结构操作和地图级属性可导出，临时实例调试值排除。
- player.cjs 职责、隐藏编辑保护、有限折线与现有距离规则不因重构改变。
- 未确认项保持待定，不引入新的 UI 框架或修改游玩侧栏。

## 建议顺序

现在：确认 ARCH-01 的分类与 ARCH-03、ARCH-05 的操作边界；标记 ARCH-02 的已提交增量，避免历史基线被当作当前完整现状。

随后：确定叠层、行为对象序列化和调试状态生命周期；为 Inspector 定义“临时修改，不随地图导出”的明确反馈与恢复路径。

实现前：将每个决定对应到迁移与验收用例，覆盖标签参数往返、虚空折线、隐藏保护、多格实体和临时值隔离。

## 排除的候选问题

- 未把“缺少 React/Vue”视为缺陷：现有栈可以实现组件与 Tab，增加框架不是必要条件。
- 未把“每个实体决定保留下层”视为需求歧义：用户已确认，剩余问题是通用合同，而不是重新选择覆盖或叠加。
- 未将结构保存与临时调试隔离本身视为矛盾：它可以实现，风险在字段分类和输出管线尚不完整。
