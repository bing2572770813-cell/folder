目标是按以下顺序收紧模块边界，保留现有玩法和数据兼容，每个独立工作单元验证后提交。不是仅拆文件或批量改写语言。

| 阶段 | 完成条件 | 当前进度 |
| --- | --- | --- |
| 1. 基础模块 | JSON、错误工具和配置边界有明确的单一实现与回归覆盖 | JSON 已统一；错误和配置待整理 |
| 2. 资源与 Prefab | 加载、继承、校验、写入职责分明，读写使用同一规则 | 已有类型适配和 HTTP 错误边界，继续整理 |
| 3. EntityWorld / Transform | 数据所有权、引用、运行时状态的接口清楚 | 待检查 |
| 4. 规则系统 | 承载、叠加和效果顺序由统一规则定义 | 待检查 |
| 5. 玩家与回合 | 规则结算与表现调用具有明确边界，玩家逻辑保留在 player.cjs | 已统一回合入口，继续整理 |
| 6. 编辑命令 | 修改通过统一的校验、执行、历史记录入口 | 待整理 |
| 7. 树与 tile 兼容桥 | 正式操作直接使用实体树，旧 tile 投影的用途受限且明确 | 待整理 |
| 8. 渲染、UI 与总控 | 按前面收紧的接口拆分状态协调、渲染和 DOM 更新 | 待整理 |

## 阶段 1：共享 JSON

`work/backend/src/core/json-value.ts` 是前后端 JSON 值校验、复制、冻结及公共类型的实现。实体模型保留原有再导出，属性模块通过 `work/core/json-value.mjs` 适配编译产物。属性深度上限 16、实体深度上限 32 和原有错误提示保持不变。

两端统一拒绝非有限数字、非 JSON 对象、危险属性名及稀疏数组。稀疏数组过去会绕过 `.map` 校验，导致序列化悄悄改变数据。后端编译、浏览器模型打包、属性测试和构建均验证此边界。
