# 回合方块需求与验收清单

更新：2026-10-07。本文记录升降、易碎、方向喷射、折线开关的已确认需求。

## 共同合同

- 实际触发原因使用互斥枚举 `Trigger.Walk` / `Trigger.Teleport`，不是组合布尔值；`enter` / `leave` 是事件阶段。
- 回合顺序：校验 → 快照 → 离开 → 位移 → 到达 → 机制结算 → 结果 → 展示 → 完成。
- 区域出口再传送到入口仍是同一回合；每个机制只结算一次，射线检查最终落点。
- 失败动作、选择、转向、等待和动画帧不推进机制。异常恢复完整快照；正常死亡保留本回合结果。
- 玩家逻辑与回合结算位于 `work/player.cjs`；组件规则负责校验，渲染读取运行结果。
- 单格纸张和地形的原有互斥约束仍适用，不新增叠层规则。
- 地图保存初始配置；撤销恢复运行状态，重开恢复初始状态。动画时长不能决定机制变化。

### 机制订阅

回合机制使用受控的 `triggerList` 连接生命周期阶段。它只声明机制关注的事件、适用的 `walk/teleport` 触发类型和处理器 ID，不保存脚本或任意表达式。处理器返回效果或更新所属运行时状态；`player.cjs` 的回合结算器负责阶段顺序、统一提交和回滚。

当前阶段连接为：

```text
beforeTransition  -> foldSwitch
afterTransition   -> rayEmitter
afterTransition   -> flame, firebird
afterMechanisms   -> lift
```

这套表是连接层，不替代机制自身的条件和效果实现。新增机制先选择生命周期阶段，再注册受控处理器；机制之间不能直接互相调用。

## 火焰与火焰鸟

- 火焰鸟与方向喷射是 `creature` 生物机关，可主动放置；自动玩家仍不可主动放置。两者保留纸面承载，不参与地形替换。受控 `firebird-placement` / `ray-emitter-placement` 行为校验完整 3×3 / 1×1 占格、可行走纸面、机关冲突及起点/入口保护；任意失败原子拒绝。两者可跟随折叠并在合法对齐时掉落。

- `flame` 是覆盖格子的运行时危险效果；它不写回地图配置。成功行动后，已有火焰向四个正交邻格扩散一层，边界裁剪并去重；本回合新生成的火焰从下一回合开始扩散。
- 火焰覆盖格不可进入。行动结算完成后若玩家位于火焰格，统一效果入口设置 `gameOver`。
- `firebird` 占据完整 3×3，配置 `direction: north|east|south|west`，静态不可进入。行动后检查中心格周围 9×9（按中心格 Chebyshev 距离不超过 4）：范围外给行动起点添加火焰，范围内生成预设方向 3×21 火焰并写入一次性 `replaced` 运行时标记。
- 火焰鸟的替换状态、火焰集合和命中结果属于运行时快照；撤销、重开和异常回滚恢复它们，保存地图仍只保留初始配置。

## 升降纸张方块

配置：`lift.minHeight`、`maxHeight`、`initialHeight`、`turnsPerLeg`。

- 升降组件属于单格纸张本体。
- 每次成功行走或传送推进一段，一单程需要 `turnsPerLeg` 回合，默认 3，范围 1–100。
- 无人占据时往返；玩家占据时只下降，最低处保持；离开后继续往返。
- 本体、标记、边线和拾取高度一起更新；编辑模式使用初始高度。
- 不新增 trigger 选择控件：保留成功行走、传送均推进的行为。

验收：

- [x] 单格归属、参数范围、行走/传送、区域传送单次结算、失败动作、占据下降、撤销与重开自动回归。
- [x] 浏览器检查与新机制同场景推进、撤销恢复。

## 易碎纸张方块

配置：`fragile: {}`，首版无耐久次数或扳机选择器。

- 成功离开后立即破碎并变为虚空，行走和传送离开都生效。
- 玩家已成功离开原格，因此不会因这次破碎失去脚下承载。
- 动画起点在碎裂前保存；源格消失后不再重采样其高度。场景刷新保留正在播放的玩家姿态，碎裂不得产生额外镜头反跳或震动。
- 移动时固定离开瞬间的世界高度；即使源格在本回合升降，也不能拖动已经离开的玩家动画。普通格、升降格进入易碎格均不得出现额外镜头反跳。
- 失败动作、预览和进入校验不破碎；后续执行异常回滚破碎状态。
- 破碎格及其附属显示从运行时投影消失，不再作为移动/传送目标；原实体配置仍保留。
- 地图保存不记录破碎，撤销与重开恢复承载。

验收：

- [x] 预制体放置、保存加载、行走/传送离开、拒绝行动、不可重入、撤销、重开、编辑与运行投影差异自动回归。
- [x] 浏览器确认离开后为空格，撤销恢复纸面。

## 冰冻射线机关

配置：`rayEmitter.initialDirection`，枚举 north/east/south/west；编辑器初始方向设置沿用现有入口。

- 首次成功行动后冻结初始朝向前方直线 3 格，之后每次成功行走/传送后恢复旧地形、反向并冻结新方向。
- 范围不含自身，地图边界裁剪，穿过阻挡与虚空；虚空、未揭示区域和破碎纸面不生成实体。
- 已有地形临时替换为 `ice_ai`；冰块是无特殊效果的蓝色阻挡实体，行走/传送不可进入。射线命中玩家时提示“被射线冻死”并结束游戏；冰块自身仍无状态效果。
- 保留格上的道具、生物、标签，以及原地形的高度和厚度。原地形组件状态保留，临时替换期间暂停。
- 多条射线覆盖取并集；只有没有射线覆盖后才恢复原地形。射线命中玩家即结束游戏。
- 显示当前朝向范围；撤销恢复方向与替换状态，重开/退出游玩清除替换。导出地图和独立游戏保存全部原地形配置。

验收：四方向及边界、首次触发、连续反向、重叠、虚空/隐藏/破碎格、道具标签保留、原机关状态恢复、拒绝操作不变、保存导出、撤销和重开。

## 折线开关方块

配置：`foldSwitch.initialState`，枚举 0/1。

- 占地 1×1，不可进入，必须位于恰好一条折线上，拒绝无折线和交叉折线。
- 只有成功使用所属折线组才切换 0/1；其他折线、普通行走和失败传送不切换。
- 每个出口通过标签 `requiredSwitches` 独立绑定开关实例 ID。仅该出口绑定的开关全部为 1 时允许触发；未绑定或留空不受开关限制。区域出口（包括无入口的揭示）及最终出口均遵循此规则，其他开关不参与。
- 出口绑定随地图保存、加载及撤销恢复；复制出口与开关时重映射所复制开关的 ID，未复制的开关保持原引用。删除绑定目标后引用保留，游玩校验提示缺失且出口不能触发。旧地图没有此字段时视为未绑定，需在编辑器中配置。
- 先结算本次折线开关，再检查本次出口；运行状态不持久化。
- 编辑器配置初始状态，游玩数字与颜色表示当前状态。

验收：

- [x] 默认配置、保存加载、无/多折线拒绝、删除折线原子拒绝、所属组切换、断开组不切换、出口门禁、撤销与重开自动回归。
- [x] 浏览器检查初始状态标记。

## 验证入口

- `npm test`：默认回归入口，包含 `work/test-directional-mechanisms.mjs`。
- `npm run build`：编辑器与独立游戏构建。
- `work/backend/test/ray-emitter.test.mjs`：回合和玩家机制。
- `work/backend/test/mechanism-document.test.mjs`：真实预制体、放置、持久化、运行时投影及标记方向。
- `work/backend/test/fixtures/mechanism-smoke-map.json`：可导入的最小浏览器验收地图。
- 浏览器步骤：导入夹具 → 俯视 → 游玩 → 点击 B3 玩家 → 行走 C3 → 检查 B3 变为空格、A4 箭头反向、三格红色射线及 D3 升降 → 撤销 → 确认全部恢复。

已验证：默认测试与构建通过；桌面浏览器上述动作通过且无控制台错误。折叠动画与手机上的像素细节尚未逐项检查，不把几何单测当作该项证据。
