# FOLD FIELD 游戏机制与跨 agent 开发交接

记录日期：2026-10-06。原代码基线：`editor` 分支 `e44caae`；纸张渲染章节及属性合同已按增量 `c6b51d8`、`446c875`、`84c158a` 更新。本文件描述已核实实现；当前已接入字段权限、entity/tag prefab、四 Tab、检视与模块化重构。后续修改机制时应同步更新本文件，并与对应功能一起提交。

> 当前规则以 `docs/entity-transform-tree-product-design.md` 及本文的更新为准。下文 version:1 JSON 和旧实例字段是兼容格式示例，实际地图保存为 version:2 实体/Transform/固定格标签。旧开发方案仅用于追溯，不应作为新实现依据。

## 1. 项目定位与术语

这是 Three.js 实现的浏览器 2.5D 方格解谜游戏及地图编辑器。目录位于 Unity3D 下，但当前可运行游戏使用 JavaScript、HTML、Node.js，不是 Unity 场景/C# 工程。

- **地图格**：二维整数坐标 `(r,c)`；`r` 为行、`c` 为列，均从 0 开始。UI 行号从 1 开始，列名 A–DX。
- **实体方块**：后端 JSON prefab 描述的可放置实体。地图保存实例属性快照，不保存对 prefab 的动态属性绑定。
- **虚空**：`tiles[r][c] === null`，不可正常行走或作为传送目标，可以保存折线。
- **player token**：带眼睛的正十二面体外观。地图放置的 token 是静态实体；游玩自动生成的唯一可控制 token 称为 **player**。
- **区域**：具有相同 `regionTag` 的实体格集合，不要求空间连通。区域名称也是出口的跳转标识。
- **折线组**：同方向、沿该方向连续相邻的折线格集合；不同方向或断开的线段分别计算。
- UI 已取消“地形”显示分类，统一称为实体。代码中的 `terrain`、`terrainConfig`、`terrainState` 是现存机制字段/模块名称，尚未重命名，不能因 UI 术语变化删除它们。

## 2. 编辑模式与地图交互

### 2.1 相机和输入

右键拖拽平移，滚轮缩放；左键用于地图编辑。Shift 不切换为相机平移。触屏单指编辑，双指平移与缩放。使用正交相机，可切换固定斜视与俯视、放大/缩小和居中；相机不支持自由旋转。

地图宽、高各为 3–128，最大 128×128。高度属性范围为 0.01–16。行走以目标格与当前格配置高度之差校验玩家的最大上移/最大下降（默认各 1），含边界；折纸和区域出口传送不受该限制，没有坡度判定或三维寻路。

### 2.2 方块工具

先在实体预览图标网格中选类型，悬停显示名称。选择 prefab 加载其默认高度、颜色、通行属性和机制；地图实例可调整高度。只有 prefab 带 `color` 时显示方块颜色栏。

- **应用方块工具**：修改已有实体格的类型、颜色、高度和机制，保留原格区域、标签、折线及实例身份。
- **放置方块**：纸张仅占一个方格；非纸张实体根据 prefab 实际占格掩码创建实例，可放在虚空或覆盖已有实体。保留被覆盖格的区域、标签与折线。
- **删除方块**：纸张按单格删除，非纸张多格实体通过 Transform 节点删除；删除实体后将其折线转入虚空折线。
- **折线工具**：逐格点击添加当前方向，移除工具清除点击格全部折线方向；不会自动铺满整条直线。
- **标签工具**：图标选择玩家起点、区域入口、区域出口或清除标签。

任一实际占用格越界或被隐藏时，整次放置拒绝；掩码空洞不检查覆盖、不修改原格。禁止将起点/入口覆盖为阻挡或篝火。删除玩家起点前需要迁移起点。

### 2.3 选区、复制粘贴与区域分配

框选工具左键拖拽矩形；Shift + 左键拖拽与已有选区求并集，可形成稀疏选区。点击虚空或 Esc 清除选区。复制保留实际选择掩码；粘贴以点击格为左上落点，越界或覆盖隐藏格时整次拒绝。

复制数据包括实体配置、子树和折线；粘贴保留目标格的区域，区域名称不随实体复制。粘贴的新实例生成新的 ID；稀疏选区未选择的孔洞不修改目的格。**当前实现剔除来源的 spawn/entry 标签，但保留 exitTo/requiredKeys；目的格已有标签合并并优先保留。** 不应沿用旧 README 中“所有起点和出口标记都不复制”的概括。

区域标签下拉可选已有区域，或选择“新建区域”填写唯一名称（1–80 字）。分配已有区域依然校验入口唯一与起点/入口互斥。若原区域最后的格被迁走，指向该区域的出口会迁移到新区域名称；若会改写隐藏格中的出口，则拒绝操作。

### 2.4 显示图层

当前 UI 包含坐标、实体清单、折纸线、方块标签、按名称显示区域。

实体清单为 prefab 预览图标 + checkbox，可多选、留空、全选和全部取消。隐藏某类型会隐藏整个实体格及附属渲染，保留地图数据。实体类型隐藏和区域隐藏在编辑模式中都参与 `cellHidden`，禁止选中、修改、删除、覆盖和对其粘贴；隐藏类型也不能新放置或粘贴。按实例删除会检查全部剩余占格。

旧地图没有 prefabId 时按机制、token 外观、阻挡属性或普通纸张分类；地图中存在而目录已删除的 prefab 也有清单项。编辑器过滤不影响游玩模式，游玩显示由已揭示区域集合决定。

方块标签开关同时控制起点、入口、出口图标。关闭网格只隐藏辅助网格，不隐藏实体自身边缘样式。网格覆盖地图内虚空，没有底部白色挡板，空格直接显示背景。

## 3. 玩家、移动与历史

### 3.1 玩家和朝向

开始游玩时，根据唯一 `spawn` 标签同步起点坐标，在该处显示自动生成的 player。起点图标不会因 player 出现而消除。静态 token 不接受玩家控制，是否可走由其实例 `blocked` 属性决定。

方向 `dir` 为 0–7：北、东北、东、东南、南、西南、西、西北。行走后朝向为实际移动方向；折纸传送后将朝向也关于折线镜像。测试任意位置传送保留朝向。旋转按钮每次改变一个 45° 档位，不增加步数，但会记录撤销状态。

### 3.2 行走和选中

左键点击 player 选中，再次点击取消。选中时高亮八向相邻的合法行走格；没有合法落点时也可切换选中。每次行走仅一步，不支持点击远处自动寻路。斜走仅校验目标格，当前没有“夹角阻挡禁止斜穿”规则。

行走目标必须在地图内、有实体、已揭示、非阻挡、非篝火，并通过当前机制进入检查。每次成功移动步数 +1；行走通过出口触发区域跳转仍算一步，不额外增加折纸传送次数。

移动动画期间不能再次移动。普通行走动画约 220 ms，传送动画约 480 ms。完成行走或传送后自动执行等价的玩家点击，重新选中 player 并显示可达落点；通关或失败后不会重新开启选区。自动选择不增加步数或撤销记录。

### 3.3 步数、结束与撤销

- `maxSteps=0` 表示不限；正值时 **steps > maxSteps** 才失败。
- 旧格式 `map.exit` 仍作为通关目标；站到该合法格即通关，不需要钥匙。
- 区域出口标签本身只负责区域跳转，不表示游戏通关。地图可以不设最终通关目标。
- 通关更新 `bestSteps`；机制死亡或超步数显示失败并禁止继续移动。
- 游玩撤销恢复位置、方向、步数、传送次数、机制状态、钥匙集合和已揭示区域。没有游玩重做。
- 重启回起点，清空进度、钥匙及游玩历史，仅揭示初始区域。起点本身是钥匙时重新收集该钥匙。
- 编辑撤销/重做记录地图与选区；连续绘制按手势合并。编辑历史最多 150 条且受约 100000 格快照预算限制，游玩历史最多 150 条。

## 4. 折纸线与传送规则

### 4.1 标记、合并与渲染

方向为 `h` 横线、`v` 纵线、`d1` ↘、`d2` ↗。实体格可以同时有多种方向，包括阻挡实体；虚空也可以独立存储标记。

同方向只沿其方向的两个邻格连接：横线左右、纵线上下、↘ 左上右下、↗ 右上左下。不同方向交叉不合成同一作用范围。每次构建/修改后重新生成连续组；删除中间标记会拆组。共线但断开的折线组保留各自半径。

折线端点位于首尾格边界，并裁剪到地图边界；不会无限延伸出地图。长虚线段长度为 1/3 格，与点交替。点使用地图空间圆形三角面渲染，随相机缩放；圆半径目前为 `0.035/3`，不是屏幕固定大小。

### 4.2 作用半径与距离

每个折线格贡献 0.5，所有方向一致。设组内有 N 格：

| 方向 | 半径 d |
| --- | --- |
| h / v | ceil(N × 0.5) |
| d1 / d2 | floor(N × 0.5) |

距离统一为切比雪夫距离 `D(a,b)=max(abs(a.r-b.r),abs(a.c-b.c))`。奇数长度取 player 到组中央格的距离；偶数长度取 player 到两个中央格的距离的**较大值**。距离 ≤ d 才可使用这组折线。单格横/纵半径 1，单格斜线半径 0；三格横/纵半径 2、斜线半径 1。

编辑模式悬停折线格时，左下提示该格各方向所属组的半径。这不是沿折线最短距离，也不是曼哈顿距离。

### 4.3 镜像落点

取轴上标记 `(ar,ac)`，`dr=r-ar`、`dc=c-ac`：

| 方向 | 镜像坐标 |
| --- | --- |
| h | `(ar-dr,c)` |
| v | `(r,ac-dc)` |
| d1 | `(ar+dc,ac+dr)` |
| d2 | `(ar-dc,ac-dr)` |

必须通过来源距离、目标边界、目标实体、已揭示区域、通行属性及机制进入检查；目标与来源相同时不能传送。折线所在格可以是虚空/阻挡，不意味着落点也可以是虚空/阻挡。

选择折线时高亮源标记与镜像落点，非法目标显示红色提示；再次点击目标、按 F 或点折纸传送按钮执行。交叉格重复点击轮换折线方向。成功折纸传送步数 +1，传送次数 +1；实际执行时再次校验落点合法性。

选中折线立即绘制贴合表面的浅色外缘与深青色细芯。作用半径内、玩家同侧的现有实体用金色实线勾勒被折叠区域，对侧现有实体用蓝色虚线勾勒目标区域；不绘制区域填充或内部公共边。折线上的实体分别勾勒两半，隐藏格与虚空不绘制区域勾线；玩家超出半径或位于轴上时仅突出折线。区域勾线用于说明折叠几何范围，实际落点仍执行通行、机制与对齐检查。区域勾线保持棋盘原位，不随纸面折叠，落点满足掉落条件时继续使用蓝色高亮。取消选择即时清理高亮；虚线提示开关不隐藏选中高亮。

### 4.4 所有合法落点提示

“折纸位移提示”默认开启。选中 player 时汇总所有折线组的合法镜像目标，与普通行走目标一起显示；同坐标去重。点击传送目标自动使用对应合法折线，无需先选线。同格同时可行走/传送时优先行走。

关闭只取消选中 player 时的折纸汇总；**单独选中折线的源/目标高亮和坐标始终保留**。切换开关立即刷新当前选择，不计步。此功能只展示单次合法落点，不计算任意多步路径可达集合。

## 5. 区域标签与钥匙条件

### 5.1 标签约束与显示

- `tags.spawn=true`：全地图唯一；必须可行走。
- `tags.entry=true`：每区域唯一；必须可行走。同一区域不能同时有 entry 和 spawn。
- `tags.exitTo="区域名称"`：目标区域必须存在，允许没有入口；若配置入口则最多一个。一个区域可以有多个出口。
- `tags.requiredKeys=["铜钥匙","银钥匙"]`：该出口传送条件；缺省或空列表表示无需钥匙。

游玩开始只显示起点区域；其他区域表现为虚空。到达满足钥匙条件的出口后累计揭示目标区域，旧区域继续显示。目标有入口时传送到该入口并保留方向；没有入口时只显示目标区域，玩家留在出口格，不触发额外传送或目标格机制。撤销恢复揭示集合。

出口入口处的机制会正常触发；一次动作只执行一次区域跳转检查，不会递归连跳整个出口链。缺少钥匙时仍可走上出口，但留在出口格并提示缺少的名称。

进入游玩前，区域入口按同格全部实体检查结构通行：必须有 surface，且不能叠加 collision 阻挡、篝火或 `static.walkable=false`。喷发周期造成的暂时关闭不使入口永久无效；运行时目标入口拒绝进入时，玩家留在出口格，提示目标区域与具体原因，不揭示目标区域、不执行离开或到达事件，也不额外计数动作。

### 5.2 钥匙实体

钥匙名 `keyName` 为 1–80 字，前后空白去除；旧钥匙默认名“钥匙”。可以存在多把钥匙。选中钥匙类型后输入名字用于放置/应用属性；框选钥匙后用专门按钮批量改名。

出口下拉 checklist 从地图中非阻挡钥匙格的名字生成，按名称去重；支持不选和多选。玩家必须已收集**全部**所需名字。同名钥匙任取一把即满足该名称；收集不消耗钥匙条件，也不删除钥匙方块。

改名后若地图上已无合法旧名钥匙，则同步更新出口条件引用；若会改写隐藏出口，整次改名拒绝。删除最后一把所需钥匙或改变其机制不会自动清除出口条件，游玩校验会报错。

## 6. 机制实体的实际效果

当前运行时以 canonical 实体组件判定机制，颜色不决定机制；旧 `terrain` 字段仅作为兼容投影。先对同格全部实体检查进入许可，再按机制优先级执行效果：危险机制先于钥匙收集，死亡后停止后续效果。实体 ID 只稳定同种效果的顺序，不决定危险与收集的先后。火焰伤害读取组件 damage，缺省为 1。

| 实体机制 | 当前规则 |
| --- | --- |
| campfire 篝火 | 不可进入；进入其八向相邻格时，若已冰冻则解除冰冻。 |
| ice 冰河 | 未冰冻时进入：设置 frozen=true，并将过热归零；已冰冻再次进入：立即失败，先于邻近篝火解除检查。 |
| fire 火焰 | 每次进入 overheat +1，达到 6 立即失败。离开火焰不会自行减层。 |
| eruption 喷发 | 初始不可进入；进入检查使用动作开始前计数，actions>0 且 actions%3===2 时允许进入，即计数 2、5、8…开放。 |
| key 钥匙 | 进入后将 keyName 加入 collectedKeys，重复收集同名无额外身份。 |

成功行走、折纸传送、测试传送各调用一次 `finishAction`，机制动作计数 +1。选中、开关提示、方向旋转不推进喷发周期。完成出口跳转后检查目标入口机制，不额外增加动作计数。

## 7. 游玩测试用选项

游玩左侧“测试用选项”subbar 收纳方向旋转、折纸位移提示与任意位置传送开关。

任意位置传送默认关闭。开启后点击地图内任何当前机制允许进入的非阻挡实体，包括未显示区域，直接传送并揭示目标区域；不允许虚空、篝火、阻挡或未开放喷发。保留方向，正常触发钥匙、危险机制和出口，步数/传送次数各 +1，可以撤销。它绕过普通行走距离和折线条件，但不绕过目标进入规则。返回编辑时关闭。

这是测试便利功能，不是正式折纸规则。独立游戏模式隐藏编辑器侧栏和测试表单；编辑器中保留这些工具供验证关卡。

## 8. 地图和 prefab 数据合同

### 8.1 地图 JSON

```json
{
  "version": 1,
  "name": "示例地图",
  "description": "说明",
  "width": 3,
  "height": 3,
  "tiles": [
    [{"color":"white","height":0.09,"blocked":false,"prefabId":"paper_ai","regionTag":"A","tags":{"spawn":true},"folds":[]}, null, null],
    [null, null, null],
    [null, null, null]
  ],
  "foldCells": [{"r":1,"c":1,"type":"v"}],
  "spawn": {"r":0,"c":0,"dir":2},
  "exit": null,
  "maxSteps": 0,
  "bestSteps": null
}
```

`tiles` 必须为 height 行、每行 width 列。地图名最多 48 字，空名回退“未命名关卡”；描述最多 240 字；maxSteps 0–999；bestSteps 为 null 或 0–9999 整数。`spawn` 坐标/方向和标签都是存储字段，游玩时以 spawn 标签同步位置。

`foldCells` 只包含 `{r,c,type}`，坐标必须在地图内；同坐标/方向去重。实体上的 `folds` 是方向数组，旧 `fold` 单值兼容保留。新增代码不可仅修改旧单值而丢失其他方向。

实体可选字段包括 `color`、`edgeColor`、`kind`、`prefabId`、`regionTag`、`tags`、`instance`、`terrain`、`terrainConfig`、钥匙专用 `keyName`，以及纸张参数 `thickness`、`gradualRate`。thickness 为 0.001–16，缺省沿用 height；gradualRate 为 0–100，缺省 2/3，含义为过渡部分总宽度除以平坦部分宽度。两者已贯通归一化并作为地图属性保存。通行使用显式 blocked；旧格缺省时黑色为阻挡。未知字段经过 normalizeTile/validateMap 会被丢弃，新增字段必须同时更新归一化、测试和导出往返。

### 8.2 Prefab JSON

```json
{
  "version": 1,
  "id": "large_paper_ai",
  "name": "大纸块",
  "size": {"width":2,"height":3},
```

ID 为 1–80 位字母、数字、下划线或连字符；name 为非空字符串。size 各维 1–128，缺省 1×1；occupied 长度必须等于面积、只能为布尔且至少一格 true，缺省全占用，按行优先索引。例子只占五格。

颜色可选 `white/red/yellow/blue/green/purple/black`；缺省 color 时 UI 不显示颜色栏，渲染使用中性白且不补写 color。edgeColor 为可选六位十六进制颜色；纸张边线为 `#414140`，独立于辅助网格。

当前纸张只能占一格。旧纸张 instance 分组及多格 footprint 导入为独立纸张格；非纸张实体仍可通过 Transform footprint 占多格，孔洞不占格。上方叠加不等于 Transform 子实体。

## 10. 渲染现状与保留要求

正交 Three.js 场景使用方块、机制图案、圆点与线段；标签使用额外渲染顺序显示在实体图案上方。纸张几何由 paper-surface.mjs 提供高度过渡，不能再概括为所有纸张都是独立平顶盒体。

**已实现：八向相邻不同高度纸张保留平坦中心，以三角面构建边缘过渡。** 相邻可见纸张参与共享边界计算：边中点取两侧高度平均，角点取共享角周围可见纸张的高度平均；虚空、非纸张及被隐藏纸张不参与。没有高度差或 gradualRate=0 时不生成过渡面。平坦中心半宽为 0.5/(1+gradualRate)。

物理厚度将底面沿顶面单位顶点法线偏移 thickness，保留底面与封闭侧面，不按固定世界高度裁剪；相邻厚度不同也各自封闭。这些几何规则不引入三维物理判定；行走高度差单独由 player.cjs 的玩家属性校验。用户已明确将平滑连接、厚度与过渡比例纳入架构重构保留清单；进一步改变算法需另行确认。

当前架构规范位于 `assets/raw_design/settings/architecture.md`；新增取舍按该文件的确认流程执行。

## 11. 重要实现边界

这些是当前代码边界，供接手时评估，不能将“期望规则”当“已经实现”：

1. 实体/区域隐藏具备修改保护；折线/标签工具、Inspector、破坏性擦除与粘贴均检查隐藏保护。撤销/重做沿用配置历史，不新增隐藏状态下的历史拦截。

玩家状态调试包含过热、冰冻、机制行动次数及已收集钥匙列表。列表采用地图上合法钥匙名称的 JSON 数组并去重，持有钥匙标记自动派生；喷发周期随行动次数同步。过热和行动次数只接受非负安全整数。调试提交不模拟进入格子的事件或推进动作，后续实际行动继续执行原机制判定，支持一次撤销及生命周期重置。

# 实体触发原因

实体事件的 `enter`、`leave`、`interact` 表示事件阶段。`trigger` 是独立的互斥到达/离开原因：`walk`（行走）或 `teleport`（传送）。处理器的进入限制与效果均收到同一个原因；初始化和原地交互不伪造行走或传送原因。禁止传入多个原因或未知值。

`ComponentRegistry.checkEntry` 仅运行组件校验和 `canEnter` 限制，不执行到达效果。行走范围预览、折纸目标检查、区域入口校验、起点及调试坐标校验使用此接口；真正到达才通过 `dispatch` 执行 `enter`，避免预览阶段误触发效果。

## 回合管理器

`work/player.cjs` 导出 `createTurnManager`、`Trigger`、`TurnPhase`。管理器通过同步生命周期钩子驱动 `validate → snapshot → leave → action → enter → settle → outcome → present → complete`。`onPhase` 收到独立的阶段状态副本；逻辑结算与表现完成分开。

校验失败不记录历史、不消耗回合。逻辑处理中及等待表现完成时拒绝新行动；结算异常恢复先前快照。`complete(id)` 只接受当前表现标识且只能成功一次；重置不复用标识，避免旧动画回调结束新回合。`reset(turn)` 用于重开与恢复快照。

实际玩家控制器的 `turnManager.execute(action)` 统一接收行走（`source: 'move', trigger: 'walk', r, c`）、折纸传送（`source: 'fold', trigger: 'teleport', axis`）和测试传送（`source: 'test', trigger: 'teleport', r, c`）。保留原有行走范围、折线及测试模式校验。一次成功行动记录一次历史、计一步、结算一次地形周期和升降机制。

行走到区域出口先以 `walk` 触发该格，到达目标区域入口以 `teleport` 触发。两次到达属于同一回合，回合根触发仍为 `walk`；自动区域跳转不额外计步或增加手动传送次数。目标入口校验也携带 `teleport`。胜负在结算后、动画前确定；结果面板等动画完成后展示。等待、选择、转向、原地交互与调试属性修改保留现有不计回合规则。撤销恢复回合状态、玩家、区域揭示和实体运行时；重开及模式切换重置回合。

自动生成 player 由 assets/prefab/entity/player_ai.json 定义：默认移动高度差与初始机制状态序列化在受控 player-controller 行为中，颜色来自 tile.color。开始/重启时克隆定义，不将临时调试反写 prefab；文件热更新只在下一次开始/重启采用状态默认值，外观使用当前目录定义。手动放置 Player 仍是静态 token，只有自动生成实例可控；状态机与交互留在 player.cjs。

### 游玩摄像机

游玩模式摄像机每帧跟随 player 渲染位置（含高度），随行走/传送动画更新；默认以玩家为中心容纳 9×9 地图方格范围。固定/俯视视角均支持，矩形窗口按比例容纳该范围，可能露出额外背景或格子，不拉伸地图。保留缩放，居中按钮恢复默认 9×9 视野。游玩允许右键平移，玩家静止时保留手动镜头，玩家移动/传送或坐标变化后矫正；自动目标按当前缩放对应的 9×9 区块限制在地图内，边界处玩家可偏离中心，小于视野的地图按地图中心显示。返回编辑恢复进入游玩前的镜头位置、目标、视角与缩放。摄像机不改变区域显示、通行或动作规则。

### 纸张实体折痕渲染
游玩模式支持临时物理折纸：选择折痕后，在玩家同侧、作用半径内的实体上向上拖拽，角度限制为 0–180°。同侧开启“可跟随折叠”的实体围绕折线旋转，折线上可折叠实体按折线切分为固定与旋转两半，player 随脚下实体旋转；相机在折叠期间暂停跟随。地图实体的静态坐标与属性不变。折线铰链高度取桌面平面（最低可见纸张底面，没有纸张则为 0），始终使用一条直轴。
player 的 `foldDrop.vertical`（默认 1）与 `foldDrop.horizontal`（默认 0.35）分别控制世界 Y 竖直距离、XZ 水平距离阈值；前端玩家属性可临时修改，prefab 可通过 `behavior.parameters.foldDrop` 提供默认值。玩家在对称合法目标上方且满足距离阈值时，目标变蓝。松开会再次校验，成功后掉落到目标（计一次折纸行动、执行原有地形/出口规则）；不满足条件或取消拖拽则回弹，不消耗行动。重启、模式切换、取消选中、撤销均清理临时折叠。原有点击/F 折纸传送入口保留。
编辑模式新增“物理属性”面板，可调试定向光、环境光、补光、阴影强度、光照方位角和仰角、曝光；立即影响编辑与游玩渲染，仅当前页面会话有效，不写入地图或 prefab。折叠最大角速度 (rad/s)：折叠拖拽时纸面渲染角度受该角速度上限约束，逐帧向指针目标角度逼近，不会瞬移；默认 2π rad/s，可调 .1–20，仅当前会话生效。折痕深度 (-1–1)：折痕下压程度，1 为完全不下压（折纸线处保持平整），0 为压穿整层厚度、折纸线处不再渲染实体；沿法线按 falloff 递减，默认 0.6（约压下方块厚度的 40%）。纸张及 token 实体参与投射和接收阴影。
纸张上的折线改为表面沿法线向内凹陷的几何折痕，凹陷深度 0.035 格、半宽 0.065 格，交叉取最大凹陷而不叠加。底面按变形后的单位法线等厚延伸，厚度属性不变。保留高度平滑连接、过渡比例、折线格合并和传送规则；虚空及其他实体上的折线仍保留标记。折线显示开关同时控制纸张折痕。

凹痕底部叠加"点线交替"的虚线勾线提示（单个长划为 1/3 纸张、之后一个圆点，周期 2/3 纸张），随表面变形弯曲；空格处的折线同样绘制，抬升到桌面平面之上。地图工具新增"折痕虚线"开关，仅控制这层提示，不影响折线本体与传送规则。

纸张放在一张 Blender 建模的等距 low-poly 桌游桌上，几何内联进独立 HTML；桌面顶面对齐地图最低纸张底面并随地图尺寸缩放。地图工具新增"桌子"开关，仅隐藏外观，桌面碰撞仍在折叠动画中生效.

## 2026-10-07：实体树与物理折叠桥接

地图仍由 TreeDocument/EntityWorld/TransformManager 管理，保存 version:2，区域属于固定格。物理折叠仅修改渲染对象；松开后合法掉落经统一 fold/teleport 回合结算一次，包含钥匙、升降、终局和撤销。掉落动画使用折叠末端世界位置，不进入地图配置。拖拽期间拒绝其他回合，失败回滚实体运行时及历史。无入口的区域出口仅累计揭示目标区域，不触发第二次到达或传送。

保留物理属性、纸张平滑连接/厚度/过渡比例、桌子和折痕虚线开关、player prefab 与摄像机跟随。共享模型的 surfaceConnected 能力决定纸面连接，升降实体继续使用其整体升降表现。详细适配及验收见 docs/backend-frontend-migration-bridge.md 第 8 节。

折叠轴位于桌面平面（最低可见纸张底面），关闭桌子只隐藏外观，不改变轴或检测基准。掉落的竖直阈值使用 player 脚部到桌面的世界 Y 距离，脚部低于桌面不可掉落；水平对齐仍以镜像目标格为准，不使用目标实体高度作为阈值基准。

实体可跟随折叠使用布尔字段 followFold；规范实体树保存为 components.physics.followFold，兼容 tile.followFold。纸张默认开启，其他实体默认关闭，可在检视中单独修改。区域内各叠加实体分别判断，不跟随的实体保持棋盘位置；玩家仅在脚下有可折叠支撑时随纸面旋转。权限、地图往返与撤销继续生效。

棋盘网格、折线虚线/选中轴/范围提示、棋盘坐标及标签提示保持原棋盘位置，不进入折叠旋转组。实体自身的边缘样式随其实体一起旋转。棋盘坐标绘制在桌面上方 0.003 格，开启深度测试，可被纸张和其他实体遮挡。

纸张实体的自带勾线统一只沿正面边界绘制，平整纸张、折痕纸张和高度过渡纸张均不绘制背面或竖直侧棱勾线；其他实体保持原边缘样式。

折痕深度允许 -1 到 0 的负值，沿表面法线形成突起，高度为绝对值乘以纸张厚度（例如 -0.5 突起半层厚度）。原有 0–1 规则不变；折痕虚线及选中提示同步贴合突起表面。
